# FMBE Studio 0.2.1 · 枪械模式

面向网易基岩 1.21.120 目标的本地造型与命令实验工作台。新增基于用户当前 AK47 存档的枪械技能、DeepSeek 生成、三姿态/换弹与纯命令导出。**本轮未重新进行网易客户端安装验证，不是完整基岩模拟器。**

## 枪械模式

1. 打开右侧“枪械”。可先载入75狐狸参考，也可直接输入“制作…枪械”。
2. 在 DeepSeek 连接中输入临时密钥。官方地址固定为 `https://api.deepseek.com`，模型 `deepseek-flash`。密钥只保存在服务进程内存；不会进入工程、日志、历史或导出包，重启后需重新输入。
3. 点击生成。系统自动加载 `fmbe-guns` 技能，模型可按需读参考并提交造型源码；系统生成实际命令、检查预算和换弹绑定，并可向模型返回预览图。
4. 完成后可预览常态/跑动/机瞄/换弹，并导出纯命令 ZIP。主文件为数字 `mccmd:1` 的命令复制助手 JSON，另有完整文本与验证记录。枪械模式不使用行为包或 `/function`。

本轮真实 DeepSeek 测试生成了72部件/72狐狸的 M4A1 风格模型，5次模型调用，累计134746 tokens（另有44-token连通测试）。这证明本次流程能完成，不代表所有枪型都自动达到同一美术质量。

0.2.1已完成五种真实生成案例：M4A1 72狐狸、MP5 73、G17 44、AWP 74、AUG 66。共26次模型调用、653780 tokens。每例均经过实际构建命令重放、身份与材质核对、动作组刚性及两次换弹归位检查。对照画面见 `assets/gun-mode/validation/index.html`；需求逐项核对见 `docs/gun-mode-audit.md`。

生成历史现在可以直接切换和载入。单次任务最多7轮；超预算反馈列出高成本部件；截图生成与实际送达模型分开记录。AUG真实调用验证了两次图像反馈送达。四个较早案例的旧版截图事件不单独作为最终图像送达证据。

压缩包内附这个真实案例：点击“打开工程”，选择 `examples/gun-m4a1-deepseek/project.json`。同目录有源码、纯命令JSON和安装顺序，不需要重新调用模型。

当前源存档有124个命令方块，已包含换弹、弹药扣除/显示、空仓休止与补弹。旧报告109块为早期状态。root表达式逐字保留，新增三目标初始化。详细说明见 `docs/gun-mode.md`。

注意：按钮“换弹”模拟源存档的换弹标签，属于视觉触发；空仓流程才启动65tick的休止与补弹链。视觉时长2.6秒与玩法锁定时间不同。手动标签本身不自动补弹。

## 启动

双击 **启动 FMBE Studio.cmd**。浏览器访问 <http://127.0.0.1:18120>。

本机已经有 Node.js 24；运行需要 Node.js 22 或更高。交付目录保留了运行依赖与构建产物，无需每次安装或联网。关闭网页不会关闭本地服务；双击 **停止 FMBE Studio.cmd** 可停止启动器创建的进程。启动器只监听本机回环地址。

工程自动保存到 `data/current.json`，修订记录在 `data/history.json`。生成记录位于 `data/ai-runs`，不包含凭据。也可以使用“保存工程”下载 JSON，或“打开工程”恢复。

## 现在可以做什么

- 用受限 JavaScript 编写参数化造型：box、beamBetween、group、arc、profilePrism、point attach、param、有界循环与组件函数。
- 修改参数或单个部件的覆盖；编译失败保持原工程；撤销/重做保留正确版本。
- 从真实原版动画资源计算通道、狐狸骨骼、held_item 定位点及最终持物矩阵。正式显示不直接读取作者目标矩阵；目标线框是独立的紫色参考层。
- 把长方体转换为方截面杆，生成五类原版动画命令。矩形截面使用有界欧几里得分解，因此某些尺寸会产生多个狐狸，计数不会假装仍为一个。
- 查看真实编译实体数、命令、部件来源、矩阵残差和预算状态。
- 尝试尺寸量化候选，比较实际实体数与最大尺寸变化。候选需要显式选择，原方案可撤销。
- 在命令实验中运行 playanimation 六个参数，检查变量、控制器和未知查询；暂停、推进、完整快照与恢复。
- 切换编辑器观察与玩家摄像机，显示狐狸/骨骼、参考线框，保存 PNG。
- 用本地 HTTP API 执行上述工作，WebSocket 接收修订通知和截图请求。无需操纵鼠标即可完成构建与读取结果。
- 通用模式导出 ZIP：工程、诊断、init/tick/clear 函数及实验行为包目录。枪械模式则导出独立命令方块链，格式见上文。

四个示例：机械臂、拱桥、带孔薄件、空间框架。机械臂初始使用 8 个部件、8 只狐狸；预算由工程设置，不写死为 75。

## 准确性与缺口

资源固定为 Mojang `bedrock-samples v1.21.120.4`，commit `091dbd3ff9cf3c4205eb3c53ba4a673374b08472`，包含 481 个动画与 168 个控制器。资源存在不意味着所有动画依赖的查询、事件与状态已完整实现。

**最重要的限制：官方资源没有公开全部物品持有引擎补偿。通用模式使用社区配方的全局推定标定；枪械模式使用当前AK47源模型的独立对照配置。它们都不是本轮在真实游戏测量得出的矩阵。** 各模式使用共享矩阵，不按每个部件目标偷偷修正。枪械配置以少量部件拟合，对其余部件和多个摄像机方向独立检查；几何残差不能代替客户端一致性验证。

尚未完成：

- 网易实际客户端构建、资源差异、物品中心/朝向、动画调用生命周期的实测校准。
- 自定义 next_state 解析、资源控制器过渡混合、timeline/粒子/声音事件的完整语义。
- Molang 全部查询、实体引用/for_each、目标数值精度与全部格式边界。
- 完整玩家动画、摄像机碰撞与姿态眼高、网络插值、裁剪/卸载、游戏物理和寻路。
- 非完整方块、二维物品、特殊持物模型、自定义资源包。
- 通用模式的任意动态运动组仍未完成；枪械模式已使用当前存档的镜头跟随、三姿态与换弹后端。
- 任意轮廓的最优分解、受保护特征自动证明、完整 Design Brief 硬约束体系、多观看者联机事件模拟。
- 完整 OpenAPI 参数 Schema、MCP 适配器，以及 DeepSeek 以外的供应商配置。

第三人称采用明确的固定 4 格偏移；界面画面和 Molang 摄像机查询使用同一个解析结果。它不模拟游戏的墙体碰撞推近。

`profilePrism` 是保守扫描条带近似，会报告跨拓扑条带和近似状态；不能把它当成任意多边形的精确实体转换。尺寸量化优化不保证锚点、孔洞和全部动作不变，选择前请检查画面和报告。

不支持的物品不会用普通立方体替代并标记成功。不支持的查询会产生诊断，不等同于游戏规定的合法零值。

## 导出与游戏测试

当前仅开放明确标注的“实验导出”。通用模式使用工程绝对坐标；枪械模式使用源存档的眼前2格载体与相机相对建模。请在用于测试的世界运行，并核对目标网易环境可用的导入方式。

通用模式 ZIP 中 README 给出函数路径；枪械模式 ZIP 给出独立命令链的顺序、类型、条件、红石与延迟。新枪与原枪使用同一类雪球/记分板玩法，迁移到已有存档前应停用原枪循环链并保留回退，不要同时运行两套系统。实验包不等于已验证导入网易。

## API

详见 `docs/api.md`。入口：

```text
GET  /api/context
GET  /api/capabilities
POST /api/agent/run
GET  /api/agent/job
POST /api/gun/action
POST /api/design/apply
POST /api/experiment/commands
POST /api/experiment/optimize
POST /api/candidate/accept
POST /api/simulation/step
POST /api/render/capture
POST /api/export
```

API 截图需要至少一个打开的工作台渲染窗口；无窗口时返回 503，不假装已截图。构建、求值和数值检查可以不打开窗口。`/api/openapi.json` 当前是接口索引，精确请求格式以 `docs/api.md` 为准。

## 开发与验证

```text
npm install
npm run typecheck
npm run build
npm test
npm start
```

测试服务使用独立数据目录和端口，不修改正在编辑的主工程。测试覆盖几何、Molang、命令重放、事务/幂等、版本冲突、回放、预算与 ZIP 内容。测试通过不能替代真实网易客户端对照。

本版46项测试通过。打包验证见 `docs/package-validation.json`；五个案例的源码、安装顺序和命令文件都位于 `examples/gun-*-deepseek`。

## 文件

- `src/core`：数学、造型解释器、Molang、命令/动画运行时、编译器。
- `src/server`：项目 API、持久化、截图任务和导出。
- `src/ui`：工作台与 Three.js 渲染器。
- `assets`：版本锁定资源、纹理与校验记录。
- `docs/architecture-reference.md`：用户提供的原始架构副本。
- `docs/resource-notes.md`：资源证据与校准注意事项。
- `docs/status.md`：本轮实际交付及后续顺序。

第三方资源及依赖信息见 `THIRD-PARTY-NOTICES.md`。
