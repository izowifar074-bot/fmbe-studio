# FMBE Studio v2：面向低成本模型的可验证造型编译架构

**状态：架构设计稿；不是已经完成的沙盒，也不是网易兼容性认证。**

目标环境：用户指定的 Minecraft 基岩版 / 网易 1.21.120。具体客户端构建、资源指纹和设置需要在兼容配置中锁定。本文所有 API、SDK 与目录名均为拟定契约。实体预算由项目配置决定，示例中的 75 不是全局限制。

## 0. 核心决定

将上一版的“动画模拟器＋API 工作台”扩展为：

> **程序化造型前端＋关系约束求解器＋实体预算编译器＋命令驱动的仿真内核＋可验证的 AI 操作回路。**

不要要求便宜模型扮演矩阵计算器、狐狸调度器、逐实体造型器或预算求解器。模型负责识别物体结构、选择造型思路、设定比例、指定重要特征并理解反馈；数值计算、预算分配、源码追踪、版本保持和固定测试流程交给软件。

三个不同的优化目标必须分开：

1. 描述压缩：一个循环或参数化组件使模型少写代码，但不会自动减少游戏实体。
2. 表示压缩：用更少的真实可实现持物原语逼近或精确表示同一形状，才会减少狐狸。
3. 执行优化：减少重复算式、命令长度、逐帧计算或传送开销，不等于减少实体。

项目成功不是“模型能输出合法 JSON”，而是“同一个低成本模型，在同等实体、模型调用和有效创作预算下，完成可落地作品的能力不低于直接写兼容 HTML 场景的基线”。

## 1. 不可违反的架构约束

- 正式效果只能来自导出命令在干净模拟世界中的执行。理想几何草图可以存在，但始终是参考层，不得冒充游戏效果。
- 高层造型器不得限制底层 playanimation 的完整语义实现。默认使用已校准的高层能力；原始命令实验通道保留全部已实现语义。
- 每个可导出的视觉原语都有目标资源、实际持物形状、可达变换、实体成本和证据状态。
- 预算是所有相关同时存活实体的约束，而非屏幕可见物体数量。隐藏、缩成零、移出视野不释放实体。
- 作者设计与优化结果分离。原始参数化设计不被优化器覆盖；失败候选不改动已批准版本。
- 任何统计都标出证据层次：解析通过、模拟通过、翻译对照通过、目标客户端测试通过是不同的状态。
- 不依赖另一个昂贵模型给便宜模型兜底；不要求训练专用神经模型；没有图像能力时仍能使用结构化观察，但不能伪造视觉理解。
- 默认单个模型、串行决策、工具内部并行算候选。多智能体不是起步依赖。
- 不把“一般网格优化”“三角面合并”或 GPU 实例化当成狐狸数量优化。
- 不宣称任意三维形状都能在任意预算下精确实现，不宣称启发式搜索结果是全局最优。

## 2. 研究依据与采用范围

ShapeAssembly 使用带连接、层级和对称关系的长方体程序表示形状，表明“关系化的形状程序”是一条已有研究路线 [S1]。我们采用表示思想，不照搬其训练网络，也不把其代理长方体输出当作 FMBE 已验证几何。

CAD-Recode 将 CAD 构建表示为可执行的 Python 代码，并使用经过专门训练的较小模型 [S2]。值得借鉴的是：利用模型熟悉的编程语法，避免仅为系统方便而发明晦涩的编码语言。该研究需要训练数据和训练，不能据此声称未经训练的任意模型具备同等造型能力。

Szalinski、ShapeCoder 展示了程序结构恢复与抽象压缩 [S3, S4]。本文明确区分程序缩短和游戏实体减少，不把前者当作后者的证明。

ToolSandbox 的结果揭示了多步骤状态依赖和工具竞争中的失误 [S5]。本文因此把已知流程、版本管理与校验交给运行器，而不是让模型反复记住操作顺序。

这些工作支持设计取向，不证明本项目已经能达到某个质量或压缩率。最终要用真实模型、真实任务和目标客户端验证。

浏览器、模型运行器、批量测试使用同一项目 API。离线测试与网页使用同一语义内核；允许不同渲染设备存在受控像素误差，但不能各自定义动画规则。

## 4. Design Brief：先保存意图，不先铺实体

每个项目保存一份独立规格：

- 对象类别、主要结构、尺寸单位、比例和期望风格。
- 全部相关场景：静态、持握、奔跑、机瞄、换弹等；不限于某一帧。
- 主要与次要观察视角、允许的玩家姿态、视场角和镜头路径。
- 真实实体峰值上限，以及可选的常驻命令、命令长度、逐 tick 操作等上限。
- 受保护的形状特征：外轮廓、孔洞、间隙、突出物、材质边界、可独立运动部件。
- 可以牺牲的细节和误差阈值；不填写时不能假定“任意牺牲都可接受”。
- 模型调用、候选搜索的计算预算，以及失败时保留最后已通过版本的规则。

用户给的硬限制由运行器保护。模型不得通过降低验收阈值、修改预算或删除测试来让作品通过。模型提出变更请求与作品修改是两种操作。

没有图片或既有几何时，第一轮由模型生成粗形并作为尚待认可的目标。工具不能凭空知道某个造型“应该长什么样”。

## 5. 面向模型的表示：熟悉语法，少量强操作，保留自由度

### 5.1 主入口不是逐狐狸 JSON 表

提供受限的 JavaScript/TypeScript 风格造型 SDK。模型可以使用常见的变量、数组、参数函数和有界循环，但只创建可声明、可检查的形状与关系。

默认只暴露当前任务需要的几个操作及示例。低层 JSON 是持久化和验证格式，不是强迫模型一次写出几百个矩阵的表格。

示意：

```javascript
const body = box("body", { size: [0.20, 0.26, 1.0], material: "dark" });
const rod = beamBetween("rod", {
  from: body.anchor("front.center"),
  to: body.anchor("front.center").offset([0, 0.04, 0.80]),
  section: [0.055, 0.055],
  up: body.axis("up"),
  material: "dark"
});
const panel = profilePrism("panel", {
  plane: body.frame("side"),
  outline: [[0,0],[0.24,0],[0.32,-0.30],[0.16,-0.48],[0,-0.40]],
  thickness: 0.055,
  material: "dark",
  motionGroup: "panel"
});
attach(panel.anchor("top.center"), body.anchor("bottom.center"));
```

这是拟定语法，不是现成可运行库。`profilePrism` 表达目标外形，绝不暗示一个任意多边形可以由一只狐狸精确实现。它必须生成带实体成本与误差的候选，或说明当前预算未找到可行实现。

### 5.2 操作按能力分层，不按特定作品写死

A. 已验证原语：定尺寸长方体、已知持物模型、平面物品等，具体清单来自版本能力注册表。

B. 关系操作：两点之间的梁、面对齐、接触、同轴、保持间距、镜像、沿路径重复、局部坐标组、旋转铰链。

C. 轮廓与构型：二维轮廓加厚、弯曲条带、多段锥形外形、孔框、环、格栅。它们是目标生成器和候选生成器，不是免费游戏原语。

D. 自由程序化组合：有界循环、用户定义的纯组件函数、公开参数和关联尺寸。新作品不必等待开发者添加“某型号枪”模板。

E. 原始命令实验：直接运行 playanimation/Molang，暴露完整底层诊断，不受高层模板限制；新配方经过测试后才提升到默认能力库。

### 5.3 空间能力直接体现在操作中

`beamBetween(A, B, section, up)` 自动求中心、长度与朝向。若 A=B，报退化输入；若 up 与方向共线，使用公开、确定的备用轴并记录。绕梁方向的滚转是必要自由度，不能靠两个端点唯一确定。

`attach` 同时说明约束哪一个面、点、法线和滚转自由度。只绑定一个点不能暗中假定方向完全确定。

`mirror` 明确反射面和材质方向策略。几何镜像不等于直接给任意物品一个负缩放：持物朝向、纹理和负行列式要由后端检查。

默认使用无环的依赖图和解析构造。确实存在闭环约束时才使用局部数值求解，报告未约束自由度、冲突约束与残差，不能任意移动其他部件让结果“看起来差不多”。

## 6. 一个作者源，不维护互相冲突的双真相

权威作者内容为：

```text
brief.json
modules/<module_id>/build.ts
modules/<module_id>/params.json
relations.json
motion.json
materials.json
```

设计图、已求解坐标、原语列表、狐狸编号与导出命令均为派生产物。

模型和界面默认修改公开参数、关系或一个模块的源码。每个派生部件携带稳定语义 ID 与来源位置。优化器产生“这个语义部件映射到哪些狐狸”的映射，而不是把狐狸编号当作者 ID。

对于循环生成的多个部件，ID 来自显式的语义键，不能只依赖不稳定数组下标。删除其中一件不应使剩余所有实体身份重排。

需要单独编辑由程序生成的某一叶子时，先查它的公开参数。没有公开参数时，要么修改对应程序，要么创建显式局部 override，并标明它是否脱离镜像/重复关系。禁止同时任意修改生成后的场景图却不更新作者源。

优化器可以合并实际实体，但不能抹除作者层的分件。以后编辑时，从作者设计重新编译，而不是反编译优化后实体去猜原来的意图。

## 7. 三种变换必须分开

### 7.1 造型变形、装配姿态、运行时姿态

- 造型变形决定单个部件的形状，例如细长、扁平。
- 装配姿态决定部件在作品中的位置与方向。
- 运行时姿态决定整个作品/运动组相对玩家、摄像机和动作时间的姿态。

默认把“改变父件的尺寸”与“非等比缩放整个子树”分开。加长主体时，连接在末端的小件应通过锚点更新位置，不应自动一起变细、倾斜或变成椭圆。子件尺寸只有在声明比例关联后才一起变化。

需要整体仿射变形时使用显式操作，保留完整矩阵并检查目标后端可达性；不能在每一层拆成位置/欧拉角/缩放后假装没有剪切。

### 7.2 坐标与单位

作者局部坐标采用一个固定的右手正交约定：+X=部件右侧，+Y=上，+Z=正前；距离单位为格，尺寸表示完整长度。正角为右手规则，角度输入单位为度。模型、玩家视点、世界朝向和原版几何单位的转换只在适配层发生。

点、方向、角度、长度与比例采用不同内部类型。不能把定位点当方向，不能混用格与原版模型单位，也不能让相机坐标向量直接进入世界空间计算。

### 7.3 高层矩阵和低层动画不是同一套接口

Microsoft 文档描述了动画按通道累积后再形成变换，默认旋转为角度、X-Y-Z 顺序 [S6]。所以不能把高层组件的矩阵相乘原样当成 playanimation 叠加规则。

后端应求解：给定目标部件变换，怎样通过该版本资源、骨骼、定位点和动画通道得到它。每个后端配方声明输入域、读写变量、控制器、时间依赖、尺度/角度范围、残差和测试证据。

静态常数可离线求解；动态跟随必须编译成游戏实际能运行的命令和 Molang。不能在网页中每帧用宿主数值优化器算姿态，却导出没有这项计算的命令。

默认高层动画用刚体组、明确枢轴和时间曲线表示。内部可以使用四元数处理连续方向，但导出要转换到支持的原版通道和表达式，并验证角度跨界、接近奇异位姿和循环边界。不能假定目标版本存在某个四元数查询或插值函数。

### 7.4 动态数值稳定性也进入后端选择

两个公式静态上等价，不代表在客户端更新阶段不完全同步时表现相同。编译器保留数值条件、极薄尺度、逆缩放放大等风险信息，优先采用已校准的稳定配方。

压缩表达式时只在已证明纯净且时序等价的范围内做公共子表达式消除；不能跨越 Molang 变量写入、查询时机或控制器状态更新随意重排。

## 8. 可实现原语注册表

每项至少包含：

```text
primitive_id / target_profile_hash
resource_model / material / holding_transform
reachable_transform_family / parameter_domain
entity_slots / helper_entities / lifecycle
animation_and_query_dependencies
material_uv_policy / visibility_dependencies
compile_static / compile_dynamic
diagnostic_probe_ids / evidence_status
```

一只狐狸持有的原版物品可能自带复杂模型，但这不意味着它的每个小方块可以独立控制。该模型是一个拥有固定内部结构、受可用骨骼链影响的渲染原语。

默认支持以当前资源和实测配方证明的能力；未验证剪切、负缩放、特定物品持握方式等不能悄悄进入正式编译。

Molang 的实体变量默认属于各自实体，公开跨实体读取还需要相应资源声明 [S7]。因此“公共相机计算只做一次供 75 只狐狸共享”不是可以白送的优化。可以复用同一程序结构和离线常量，但运行时重复计算成本仍要按实际实体计入。

## 9. 实体预算优化器：让软件搜索，不让模型逐件删

### 9.1 预算模型

正式上限为：

`max_t (display_entities(t) + helper_entities(t) + transitional_entities(t)) <= B`

初始化、动画过渡、加载恢复和热更新也计入生命周期。若采用预分配实体池，预算至少覆盖池大小；被隐藏的备用实体仍然存在。编辑器节点、共享模型资源和 draw call 数不能代替这个值。

预算计数最终由部署计划和命令重放结果相互校验。初期按静态分配峰值保守计数，比把未验证的实体复用当节约更可靠。

### 9.2 先提取自然的压缩单位

按稳定相对运动、几何连接与材质边界分组。静态看起来挨在一起、换弹时会分开的两个件，不得跨运动边界合并。动作绑定应在优化前进入设计，不是优化后补上。

每个组保留作者原始方案；优化失败时存在可回退基线。

### 9.3 两条不同优化通道

**等价通道**：只接受可验证的等价改写，例如相同形状的重复覆盖、特定共线分块的几何合并。几何等价不自动等于纹理等价或时间行为等价。

**近似通道**：按已声明的阈值和视角，用更少可实现原语逼近目标，例如弯曲条带用较少的长条分段，次要圆柱轮廓用更少的径向构件。

近似通道必须记录牺牲的细节、误差发生在哪里及所选预算；不得把近似结果标成无损。

### 9.4 材质等价是独立问题

十个同种方块相连与一个拉长十倍的方块，即便几何外壳相同，纹理重复次数和朝向也可能不同。判断合并时需要分别检查几何、纹理/UV、材质边界、动作与可见性。

对低细节材质，用户可以允许特定纹理差异；对条纹、木纹、网格等，不能只因 item_id 相同就宣称等价。

### 9.5 候选如何产生

不使用“任意复杂模型→自动最优分解”这样没有实现内容的黑箱。候选由具体、有界的算法产生：

- 直线构件用两端点和截面构造一根可达长方体，而不是沿对角线逐格铺方块。
- 曲线构件先在二维主平面中找少量分段，再转为有方向长条。根据曲率和轮廓误差自适应分段，不均匀浪费预算。
- 平面轮廓优先用少量已实现原语拟合，保留孔洞与尖角。二维分解减少了搜索维度，但多边形/三角网格不自动成为一只狐狸。
- 对规则重复结构，枚举少数密度和截面变体；程序共享和实体数量分别报告。
- 固定物品模型候选必须来自版本注册表，且检查实际纹理和变换域。
- 一般网格导入只提供受限拟合，报告距离/轮廓误差；不用凸分解块数或三角面数代替实体成本。

### 9.6 全局预算分配

对第 i 个分组，生成候选 k：真实实体成本 `c[i,k]`，几何/轮廓/材质误差，命令开销及稳定性信息。

简单版本用多选背包动态规划，选择每组一个候选，使总成本不超过可用预算，代理损失最小。允许省略的装饰件可以有“省略候选”；受保护部件不允许。

`D(i,b) = min_k { D(i-1,b-c[i,k]) + e[i,k] }`

该最优性只针对给定离散候选、独立损失和该预算模型，不是连续几何全局最优。候选之间的遮挡和轮廓交互会使总视觉误差非可加；动态规划之后必须渲染整件，进行局部交换/细分/重拟合并重新检查预算。

有复杂共享约束时可接入 CP-SAT 等离散求解器，但它不能直接替代连续几何和渲染评估。CP-SAT 文档明确区分 OPTIMAL、FEASIBLE、INFEASIBLE 与 UNKNOWN [S8]。项目报告应保留这种区分，并说明“不可行”只针对被编码的候选问题。

### 9.7 不用一个伪精确总分掩盖取舍

先满足硬约束，再比较候选。输出若干不可相互支配的方案：更省实体、形状更接近、运行开销更低或风险更小。每个报告给出真实计数和损失位置。

约束/指标可以包括：轮廓差、关键点偏差、表面距离、孔洞是否保留、材质边界、各动作完整性、数值条件、命令长度、实际逐 tick 操作量。没有外部目标时，不输出伪造的“美观度 97 分”。

### 9.8 哪些事情不能保证

仿射变换后的实心长方体仍是凸集，不能单凭旋转和拉伸产生一个真正带孔的环。其他原版物品原语会改变可达集合，但不能无视它的固定结构。

同样，已高度压缩的 75 实体作品未必还能大幅降低数量。工具必须报告找到的最好方案及限制，不能预先承诺减少某个百分比。

## 10. 摄像机和动作参与造型目标，但不能成为作弊开关

第一人称作品的重点可以偏向常用观察路径；但测试集合至少覆盖正常持握、关键动作、快速转向和允许的玩家姿态。辅助观察视角用于发现侧面漏洞，具体权重由 brief 保存。

不得只对一张截图优化。一个平面剪影也许能骗过单视角轮廓，但在转动和动作时失真；因此同时使用多视角、多动作、深度/厚度和受保护特征约束。

永久背面简化是可选的“受限视域方案”，须明确适用范围；默认通用模式不能删除偶尔会露出的面。重要孔洞即使屏幕面积小也应受保护，不能仅按像素面积分预算。

玩家、玩家客户端摄像机和编辑器观察摄像机分离。拖动编辑器不能改变被模拟观看者的 q.* 查询结果。

实体跟踪、动画评估、实体渲染边界裁剪、物品裁剪和遮挡分层保存。不能通过编辑器直接强制显示全部物品来绕过狐狸可见性问题。

## 11. AI 回路：把数字搜索和固定流程放进工具

默认一次工作循环：

```text
读取当前模块与目标
→ 提交一个局部设计修改
→ 工具检查并在候选分支编译
→ 工具内部搜索有限候选
→ 用真实命令运行固定场景
→ 返回问题摘要、候选与来源
→ 模型选方案或修改造型关系
→ 通过门禁后提交
```

“工具内部评估几十个角度、分段或预算分配”不要求几十次模型调用。模型决定离散造型思路，工具负责可量化的参数搜索。

运行器自动完成类型检查、计数、编译与规定测试，不依赖模型记得调用每一步。未经当前修订检查的导出操作会被拒绝。

一个便宜模型即可完成串行决策。不同候选可以在本地 worker 并行模拟；不要为了“架构先进”而默认安排多位模型互相评论。

## 12. 最小常驻工具面

建议初期常驻五种工具族：

1. `context.read`：返回当前 brief 摘要、预算、模块、锚点、公开参数、未解决问题和已验证能力。
2. `design.apply`：按修订提交参数修改/模块源码/关系修改，原子执行，错误时不留半成品。
3. `experiment.run`：编译、按预算生成候选、运行测试，返回可比较结果。研究原始命令可通过按需加载的实验工具访问。
4. `candidate.accept`：提交已验证候选及其证据，保留之前版本。
5. `project.export`：运行必要门禁并导出当前已通过命令及部署说明。

`diagnostics.explain`、`library.lookup`、低层命令工具按需提供，不必同时把几十个工具和全部动画字段塞进模型上下文。

工具名称不重要，边界重要：外层函数严格约束结构，源代码还必须经过自己的语法和语义检查。JSON Schema 正确不能证明造型正确。

### 12.1 状态与事务

每次变更包含 `base_revision` 与 `request_id`。重试返回原结果，不重复召唤实体；版本冲突不静默覆盖。候选运行引用不可变资源指纹、场景、种子和作者修订。

模型不能修改测试报告、资源证据等级、原始测量记录和 hard brief。导出命令通过一个安全命名器生成，自定义标识符遵守用户的网易过滤限制；固定原版命令/资源名不被误改。

### 12.2 API 供应商适配

模型服务与沙盒 API 分离。本地运行器负责请求模型、执行工具、收集反馈。密钥不进入项目和浏览器前端，不要求向公网暴露沙盒。

DeepSeek 官方 API 提供函数工具、JSON 输出和带条件的 strict 模式；具体端点与模型选项以适配器能力记录为准 [S9]。不能以“某个品牌”作为是否支持图像的硬编码判断。

支持 strict 时尽量使用其支持的简洁模式；不支持时用结构化输出/工具响应加本地校验与小范围修复。没有必要把编译器正确性寄托于模型服务一定守格式。

## 13. 让 AI 易读：观察不是转储原始状态

默认观察包包括：

```text
项目与修订
本轮目标 / 不得改变的约束
整体尺寸与主比例
模块树（语义名称、成本、状态）
当前模块公开参数与输入/输出锚点
实体预算：分组成本、辅助实体、峰值
关键轮廓/孔洞/间隙测量
上次修改实际造成的变化
最多若干个最重要问题
每个问题对应源码或公开参数
```

点开问题才读取更深层的变量、骨骼矩阵和原始命令。多层压缩应由工具从结构化事实生成，而不是靠一个模型总结另一个模型的日志。

错误示例：不要只返回“矩阵错误”；应返回“连接点 c12 的期望位置与实际位置相距 0.03 格；误差来自 panel.length；body 及 rod 没有变化”。数值应为实际计算结果，本文示意数字不是测量。

有视觉能力时提供固定视角的简洁截图、部件编号和必要的差异图。没有视觉能力时返回多视图投影包围盒、关键点、轮廓采样、关系与度量；工具不能把这些度量自动冒充完整视觉审美。

没有目标参考时，报告“当前长宽比为多少”，而不是假装知道“正确长度是多少”。用户仍然可以直接判断画面并修改 brief。

截图、查询与读取轨迹不推进时间、不重跑表达式、不改变变量。多视角截图消费同一不可变帧状态。

## 14. 提示词只负责分工，不负责保存实现知识

默认系统提示应短，当前状态由工具实时提供。示例见 `agent_prompt.md`。

不把整份架构报告、全部原版动画和所有失败记录塞进每次模型请求。按当前模块检索少量可用操作、一个正确示例、一个必要边界和已有失败条件。

成功组件成为参数化库条目：含源码、可调参数、成本函数、资源指纹、测试场景、证据等级和失败边界。成功不是保存一句“这样做可以”；失败不是保存一句“这个公式不好”。

后续可以做模板检索与自动抽象，但首版不依赖训练 ShapeCoder 类模型或引入庞大 e-graph 引擎。先把常见重复结构显式编成库函数。

## 15. 仿真内核仍需完成的工作

这一层继承上一版需求，但不把复杂性暴露给日常造型模型：

- 目标版本资源加载、格式兼容、依赖和指纹。
- playanimation 全参数解析与目标执行、控制器身份、停止表达式副作用、重发与混合生命周期。
- Molang 语法、作用域、查询上下文、精度/数值边界、错误行为和执行预算。
- 动画关键帧、通道合成、覆盖、循环、时间更新、状态机、事件及资源引用。
- 狐狸 world/root/body/head/held-item 相关层级、持物姿态、几何、材质与可见性。
- 服务端状态、每个观看者客户端状态、帧输出分离；逻辑 tick、消息/状态更新、渲染帧、动画局部时间分离。
- 玩家输入、实际摄像机与编辑器观察摄像机分离。
- 命令方块调度、初始化、持物、编号、标签、记分板、必要的世界条件与生命周期。
- 快照包括所有状态和待处理事件；回放从检查点重放，不通过直接改时间伪造历史。

未实现的查询或语义不得偷偷返回 0 冒充通过；游戏本身规定的错误结果和模拟器未实现的能力是两种诊断。

默认不先复制完整生存、无限地形和寻路系统。某个测试依赖尚未模拟的游戏状态时，要标明缺口；可注入的测试状态与由游戏规则计算出的状态不同。

## 16. 独立对照与翻译验证

只让编译器和它共用同一错误的渲染器互相验证是不够的。

建议建立三路对照：

A. 作者几何参考求值器：根据公开数学规范求目标几何，用于检查编译后的部件是否达到目标。
B. 命令仿真器：只执行实际导出命令，不能读取作者目标矩阵替它修正。
C. 目标网易客户端：使用可观察的物品关键点、轮廓、动作和裁剪行为作外部校准。

A 与 B 可以共享基础数据结构，但关键变换测试须有独立实现或解析性质测试。纯数学一致性不证明客户端时序一致。

对每个编译候选建立可追踪对照：源部件→原语→实体→动画贡献→屏幕测量。重组问题要分别测“整件公共偏移”和“部件相对变形”。

动态场景采用固定测试与随机/边界压力测试；通过采样不自动变成覆盖全部连续状态的形式证明。能解析证明的性质与仅采样通过的性质分开标注。

## 17. “不比 AI 自己写 HTML 差”的验收设计

### 17.1 表达能力不退化

在同一已验证原语、材质与变换域内，能够导入或重建直接 HTML 的每个部件与动画关系，保留为基线候选。基础长方体的任意合法旋转和非等比尺寸不能因为高层接口简化而丢失。

不承诺任意 Three.js 着色器、任意网格、任意 DOM 页面或未验证动画一键无损变成原生命令。支持的导入子集明确列出；其他输入只成为理想目标，不是假装可导出的成品。

### 17.2 同模型对照

对照 A：模型直接写受相同原语/材质/预算约束的 HTML 造型。
对照 B：仅基础增删长方体的接口。
对照 C：本架构的参数化、约束、预算与反馈工具。

保持同一模型与端点版本、输入需求、实体预算、模型调用/令牌额度；另计本地优化时间和硬件成本。没有图像能力的模型三组都保持相同能力，不给其中一组隐藏的强视觉模型。

### 17.3 测试内容

从直梁和简单对称结构，到弯曲轮廓、带孔构型、复杂机械外形，再到动态换姿与局部修改。保留部分未出现在组件示例中的新题，防止只会拼模板。

重点测：有效完成率、硬约束违反率、实体峰值、源几何和正式效果差异、目标轮廓与孔洞保留、动态稳定性、局部编辑是否破坏无关部件、令牌/工具调用、用户盲评。

### 17.4 保底原则

已有合法基线在候选集合中保留。自动优化不得在受保护指标上越过允许阈值，不得覆盖唯一已通过方案。对于审美而非硬测量的取舍，不假装存在自动绝对排序。

这提供工程上的防退化机制，不是对所有未知任务都必胜的数学承诺。

## 18. 技术选型与代码边界

采用单体模块化本地应用，不先拆十几个微服务。

- TypeScript：项目模型、造型前端、几何求解、基础预算分配、API 和模拟内核。
- 独立解释执行的受限造型程序：无网络、文件、DOM、进程权限；有时间/内存/循环预算。不能把普通 Node VM 当足够安全的任意代码隔离。
- Worker：并行候选运行与渲染，默认唯一逻辑语义内核。
- Three.js 等渲染层：消费真实几何和矩阵，不负责决定游戏动画语义。
- 本地服务：模型工具调用、项目修订与资源管理；密钥隔离。
- 文件＋运行索引数据库：作者源可读，测试产物可回溯；资源按许可与用户本地导入策略管理。
- 后续可选专用求解进程：只接受已求值的离散优化问题，不再实现第二套动画物理。

推荐模块边界：

```text
packages/
  design-source/        # brief、模块源码、参数、关系、稳定 ID
  authoring-sdk/        # 常用造型操作、类型检查、执行限制
  geometry-solver/      # 约束、坐标、轮廓候选、独立几何参考
  budget-compiler/      # 真实实体成本、候选选择、损失报告
  capability-registry/  # 版本原语、配方、资源和证据
  fmbe-lowering/        # 目标变换→原生命令、部署和来源映射
  bedrock-runtime/      # 命令、Molang、动画、狐狸、客户端时间
  observation/          # 简洁语义状态、追踪、截图和差异
  verification/         # 端到端重放、性质测试、外部校准
  model-runner/         # 供应商适配、上下文、事务、调用预算
apps/
  local-server/
  workbench/
```

## 19. 应调整开发优先级

不要先造一个全面模拟器，最后才发现低成本模型不会有效建模。也不要先做漂亮编辑器，再补正确性。

第一条纵向闭环就应覆盖：一个低成本模型可用的短模块→两点梁/连接点/旋转→真实狐狸持物变换→真实命令预览→预算计数→一个局部修改→结构化反馈。兼容状态仍如实标明。

随后加入轮廓与多候选预算分配，直接验证模型易用性和 HTML 基线。并行扩展底层 playanimation/Molang 覆盖与实机校准。

在这一小闭环通过前，不投入复杂多智能体、任意网格全自动重建、神经网络训练、复杂全局最优或华丽 UI。

对当前 FMBE 经验，应导入既有 75 实体作品、已知错误版本与修正版本作为回归。它们是测试，不是让模拟器识别“这把枪”后打补丁的理由。

## 20. 交付门禁

正式宣称某版本适合创作前，应至少检查：

- 几何原语的可达域与单位测试通过，简单旋转/非等比尺寸没有接口损失。
- 全程使用真实命令执行；正式图与目标草图不会混淆。
- 动作边界、材质与孔洞不会被实体优化静默破坏。
- 峰值计数覆盖初始化、隐藏实体、辅助实体和切换场景。
- 有可回退基线，版本冲突、工具重试与非法输入不会破坏工作区。
- 至少一个实际低成本模型完成端到端建模与局部修改；记录而非想象其能力。
- 相同模型的 HTML 对照不会因接口限制而无法重建。
- 模拟与实机证据分离，没有误报“全部网易验证”。

## 21. 附带探针的边界

附带 `design_probes.py` 检验两项纯软件设计性质：两端点构造有方向长方体的数值一致性，以及有限候选多选背包与穷举的一致性。它不执行 Minecraft、不实现 Molang、不证明材质或动态效果，也不是完整优化器。

这类小探针用于避免让“求旋转”和“自动分预算”只是口号；真正交付仍需第 16～20 节的验证。

## 22. 最后决定

本项目最应保存为可执行软件的，是强模型现在能够使用的那部分方法：局部坐标、连接关系、运动分组、可达原语、预算分配、错误定位、版本保持和测试。

低成本模型不应重新发现这些方法。它面对的界面应接近“用少量代码描述设计，再从可信候选中作决定”，而不是“在几十只狐狸的变量表中猜矩阵”。

真正的成功标准：**创作自由度不因接口收窄而下降，工程正确性不依赖模型记忆，实体优化有实质算法，效果提升有同模型对照证据。**
