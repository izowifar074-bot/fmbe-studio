# 工作范围

负责游戏造型、部件比例、材质、动作组和局部修改。狐狸身份、原版骨骼映射、root 运输、帧补偿、长 Molang、弹药/换弹和命令块调度交由枪械编译器。

先通过 `gun_reference` 阅读当前基线摘要及 geometry 指南；需要参考 AK47 比例时再读取 model。使用 `gun_submit` 提交完整受限 JavaScript 源码，查看实际实体数及诊断后修正。不要只描述将要制作的内容而不提交设计。

## 版本与范围

- 当前存档为 **124 个世界命令块**，另有 16 条结构模板命令。报告的 109 块是旧版。当前 R001 已安装 C23 换弹；root 表达式逐字未变。
- 常态/跑动/机瞄/换弹、雪球触发、ammo/fire/reload、休止与补弹均存在于当前源码。不能继续说“没有弹药逻辑”。本轮程序对照不等于重新在网易中验证。
- 新世界需要单独创建 fire、ammo、reload 三个 dummy 目标。源存档已存在这些目标。
- 保持单人纯命令交付，不用资源包/行为包/脚本 API 或 /function 替换枪械运行链。导出为数字 `mccmd:1` 的 sections/items/cmd/block 格式与完整文本。

## 模型表达

空间为游戏格：**X 枪口前方，Y 上方，Z 侧向**，中心与全尺寸；角度输入为度，模型旋转 Rz×Ry×Rx。常见步枪视觉长度约 1.2～1.5 格，仅为游戏造型尺度。

使用 box、beamBetween、group、arc、param 和有界循环。保留稳定 ID 与有意义的 name。group 可用英文 ID；部件 motionGroup 可为 `magazine`、`bolt`、`static`。

- 弹匣的主体、底板、侧棱属于同一个 `magazine` 动作组，不能把棱线留在机匣上。
- 拉柄/枪机可动件用 `bolt`；其它部件用 `static`。
- 同一长方体若两条尺寸相等，通常只需一只狐狸；三轴任意不同可能需要多个狐狸。按 gun_submit 的真实成本判断。
- 材质优先 black、gray、acacia、iron。黑灰色用于区分机匣/管件/细节；木质是否适用取决于要求的枪械风格。
- 参考案例 75 个部件/75 狐狸，分为机匣12、枪托7、握把护圈9、弹匣24、护木6、枪管导气8、瞄具9。不要把“接近参考水平”降成五六个大盒子；也不要机械地复制 AK 的弯弹匣和木托到所有枪型。
- 优先保留可识别轮廓、握把、护圈孔、弹匣、护木、管件、瞄具、材质层次。预算紧时减少重复小棱线/铆钉，保留主体与动作组。
- 枪械编译器会从当前部件重新生成编号表和换弹组 ID，不要在模型里手写 k13 或狐狸矩阵。

## 不变量

root 采样与运输必须保持当前命令原文：M1、alpha 回绕、3 次预热、L1>3 清零、固定骨骼补偿。姿态只有一个持续驱动；信号只写目标并 return 1。渲染一次安装，跟随每 tick。默认不改这些机制来调整枪的外形。

详细约定按需读取：

- [geometry.md](references/geometry.md)：可用 SDK、比例与实体成本。
- [runtime.md](references/runtime.md)：身份、root、姿态、换弹、弹药和开火。
- [evidence.md](references/evidence.md)：当前124与旧109差异、证据边界及失败经验。

不得将“模型已生成”“离线检查通过”“命令包格式通过”“目标客户端实测成功”混为同一种结果。遇到错误按具体诊断修复；不要删除诊断、改变预算或伪造测试来通过。
